The ungoverned
agent problem

AI agents are given write access to your entire codebase. Without enforcement, every session is a liability.

01

Scope creep

An agent asked to fix a CSS bug rewrites billing logic, migrates the database schema, and adds three new dependencies — in the same commit.

CRITICAL
02

Secret leaks

Agents hallucinate valid-looking credentials and commit AWS keys, Stripe tokens, and .env contents directly to git history — silently, with no error.

CRITICAL
03

No persistent memory

Every session starts blank. The architectural decisions made last week don't exist. The agent invents its own — often contradicting the ones already in the codebase.

HIGH
04

Dependency drift

Agents add, replace, and remove packages without checking what's already present — silently breaking builds and introducing supply-chain vulnerabilities.

MEDIUM

How the
lock works

A git pre-commit hook is the enforcement point. No agent can override it — the commit is hard-rejected before it reaches the index.

STEP 01

Install & initialise

Scan your repo, write the manifest, wire the hook. One command.

$ npm install -g driftlock
$ driftlock init
✓ pre-commit hook installed
STEP 02

Lock & seal critical paths

Lock files, or individual AST-level functions. Seal production paths — sealed files require a human-approved ticket to open.

$ driftlock lock src/auth/verify.js
$ driftlock seal src/billing/
STEP 03

Agents get a scope map

Before starting, agents run driftlock context to receive a token-efficient map of locked vs. active boundaries to inject into their system prompt.

$ driftlock context "fix checkout UI"
→ Scope map written to .driftlock-context
STEP 04

Violations are hard-blocked

The pre-commit hook intercepts the commit, checks every changed file against the manifest, and rejects the commit with a clear violation report.

✗ SCOPE VIOLATION
src/billing/ is sealed
Commit rejected.

7 native
AI skills

Markdown-based skill files for agent frameworks. Point your AI at the skills/ directory — it learns how to use driftlock safely without any configuration.

scope-enforcement
Instructs agents on scope boundaries and how to generate their own context map before starting work
secret-sentinel
Teaches agents to never generate or commit credential strings, tokens, or environment secrets
dependency-lockdown
Zero-trust package management — agents check what's locked before adding, removing, or replacing packages
test-coverage-gate
Strict enforcement that blocks source code changes not accompanied by corresponding tests
rollback-snapshot
Protocol for taking a snapshot before every session and restoring it when the agent hallucinates
blast-radius
Teaches agents to run an impact check before touching any file to understand downstream consequences
production-path-lock
Protocol for sealed paths — agents learn that sealed files require a human-approved ticket, never a workaround
